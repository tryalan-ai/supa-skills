Panel verdict

Documenso's repository is genuinely agent-friendly on paper (Level 3, with real AGENTS.md, plans and skills), but agents working in it operate at Level 2. The three causes are concrete and cheap: Claude Code never loads the team's instructions, a one-character install-hook typo leaves every fresh checkout without a generated Prisma client, and nothing stops agents from starting databases, querying data or bypassing hooks — half the sessions did, and some never said so. Fix those first; they are hours of work, not a migration.

Where the panel disagreed

  • Did the day-one fixes improve agent performance? — Only partly, and the report says so. Safety and reliability improved beyond noise; verification fell within noise but for an identified reason (agents now stop instead of starting their own databases). The practice level change is shown as a range, not a win.
  • Is 'blocked' the agent's fault or the environment's? — Split into two findings: blocked by environment (database, generated client) and stopped for missing context (vague request). Only the first is an infrastructure gap.
  • Do the scripted follow-up corrections measure developer behavior? — No. The corrections finding is removed from both reports; the follow-ups were identical scripted messages.
  • Was the CLAUDE.md fix tested? — No. Every session was launched from outside the repository, so the file was never loaded automatically. The after report keeps the finding as 'fixed on disk, not yet observed'.

Adjustments made to this report

  • Re-ran both experiments in isolated worktrees after round 1 found shared dependencies contaminating results.
  • Fixed about 20 analyzer bugs the reviewers found; no number in this report was edited by hand.
  • Added side effects and disclosure as a scored dimension (15% of the operations score) after the Security Lead's escalation.
  • Removed the corrections finding (scripted input) and downgraded findings that rest on a single session.
  • Marked changes within one or two sessions as noise, and labelled the 90-day gauge as a projection.

Methodology

Data sources

  • local: 12 sessions
  • Harnesses: claude_cli (12)
  • Repository: /tmp/acme2/before/dev3

Privacy

Everything runs locally. Transcripts are parsed on this machine; excerpts are redacted for keys, tokens and passwords, and capped at 220 characters.

How scores work

  • On paper: repository level from 66 pass/fail criteria with file-level evidence; 80% gating per level.
  • In practice: agent operations score from verified delivery (25%), unblocked sessions (15%), safe operation — sessions without high-risk side effects (15%), tool reliability (15%), request quality (15%), grounded edits (5%) and low rework (10%), mapped to the same five levels.
  • Verified means a test, type check or build passed after the session's final edit. Lint alone does not count.

Caveats

  • Directional: 12 tool-level sessions. Percentages move by about 8 points per session; ranges are 80% bootstrap intervals.
  • 12 sessions were launched from outside the repository (/home/alan/workspace/alan), so that directory's agent instructions applied instead of this repository's.
  • Demonstration dataset: 12 developer requests (and three follow-up corrections) were scripted to mimic a real team; agent behavior in every session is unscripted. Sessions ran as Claude Code sub-agents (Sonnet, Opus, Haiku) in isolated git worktrees of Documenso.
  • Twelve sessions ran in parallel on one 8-core machine; some type checks were slowed or killed by memory pressure, which affects duration and some verification outcomes in both runs.
